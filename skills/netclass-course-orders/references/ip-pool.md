# IP 池 / 出口代理方案（网课多账号场景）

> ## ⏸ 当前状态：**已调研，暂未启用**（2026-10-14 决策）
>
> - **现状**：全部走本机出口。已核实：启动脚本/代码里**没有任何** `--proxy-server` / `http_proxy` / `socks5://`，
>   笔记本上带调试端口的浏览器进程命令行也**不带 proxy 参数**。
> - **决策**：这单及后续初期仍用本机出口（够用、少一层变量）；IP 池方案**先写进文档，等触发条件出现再启用**。
> - **触发条件（出现任一条就该启用）**：① 同一平台要同时跑 ≥3 个不同**账号**；② 平台开始按 IP 判风控
>   （同 IP 多账号被关联 / 频繁短信验证 / 异地登录提示）；③ 需要长时间多账号并行，担心出口被盯上。
>
> ### 启用清单（照着做，一次到位）
> 1. **买出口**：先 1 台 **ADSL/动态拨号 VPS**（¥6/天量级）验证；量上来后**一账号一条**出口。
> 2. **探测**：确认这台出口 IP 的家宽/城域网属性、带宽能否扛住并行路数（配合 `parallel-probe.mjs`）。
> 3. **接进实例**：在 `runs/remote/start-<平台>.ps1` 里给**对应实例**加 `--proxy-server=...`；
>    **不动系统代理、不写全局环境变量**（与技能 `cn-proxy-pool` 的铁规则一致）。
> 4. **映射表**：维护"账号 → profile → 出口 IP"对照（放订单目录，不入库），**一个出口只跑一个账号**。
> 5. **验收**：`curl --proxy ... https://api.ipify.org` 看出口；页面里 `fetch('https://api.ipify.org')` 复核；
>    登录一次看是否触发短信/异地提示；跑一轮 `parallel-probe.mjs` 确认并行不掉速。
> 6. **回滚**：去掉启动参数即回到本机出口（改动只在启动脚本一行，随时可撤）。
>
> ---

> 目的：**每个账号一条独立出口**，避免同 IP 多账号被关联风控。

## 二、怎么接进 netclass（关键：不要动系统代理）

浏览器出口用 **Chrome 启动参数**指定，**一个浏览器实例 = 一个账号 = 一条出口**：

```powershell
# runs/remote/start-<平台>.ps1 里给对应实例加这一行（示例）
--proxy-server="http://USER:PASS@IP:PORT"
```

- 改的是**那一台浏览器实例**，不是系统代理；与技能 `cn-proxy-pool` 的铁规则一致（不设系统代理、不写全局环境变量）。
- SOCKS5 同理：`--proxy-server="socks5://IP:PORT"`（本机自建时用 `ssh -D` 或拨号 VPS 上的 socks 服务）。
- 每个账号一份 profile + 一条出口 IP，**不要在同一个出口上跑两个账号**。

## 三、验证出口与风控（接完必做）

```powershell
# 1) 出口 IP 是否生效（走代理看 IP）
curl.exe --proxy "http://USER:PASS@IP:PORT" -s https://api.ipify.org
# 2) 页面里确认（同一浏览器实例）
node scripts\nc.mjs eval --port 9227 --target "<域名子串>" --expr "fetch('https://api.ipify.org').then(r=>r.text())"
# 3) 登录一次，观察平台是否触发风控：异地登录提示 / 短信验证 / 强制改密 → 有则换"同城"或"住宅/移动"出口
```

## 四、纪律

- **免费代理不碰账号流量**；只用于无凭据的连通性测试。
- 换 IP 别机械（拨号 VPS 按"每单/每天"换，别每请求换）。
- IP 只是风控的一环：平台还看设备指纹、Cookie、行为节奏 —— 换 IP 不能替代"别把行为做得像机器人"。
- 代理配置只落在**单实例启动参数**里，用完清理，不在系统里留痕。
